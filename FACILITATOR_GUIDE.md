# Facilitator guide — THE FINAL BRIEF: Choose It. Build It. Prove It. (online)

**Goal:** close the session with a project: participants choose the AI approach that best fits a work task, explain why, build it (a prompt, a custom assistant, a conversation plan or an automation), review it, and get feedback.
**Format:** individual, 15–20 minutes + 5–7 minutes of debrief. Use it after the course content, as the closing activity.

## Know the source before you present
- It follows the course’s capstone module: match tasks to assistant types (Generative · Conversational · Automation), use the 5-component framework, validate outputs. The deck has no worksheet for this; the four tasks, the rubric and the feedback texts are written for this game and are fictional scenarios. The debrief questions are suggestions.
- **The game does not run an AI.** It checks the participant’s choice, reasons and written build with a transparent keyword/structure rubric — whether the elements are there, not whether the result is good. Say this out loud, and ask everyone to test their build afterwards in an approved tool with made-up data.

## Before the session (5 min)
- Open the link → Trainer (PIN 2026). One session per group (**+ New session**). Put the **player link** (or the 5-character code) in the chat.
- Remind everyone: use [placeholders] and made-up examples — never confidential, customer or personal data (the relay is public).

## The four tasks (and the best approach)
1. **The Long Report** — summarise a public 40-page report for a manager. Best: **one-off prompt** (acceptable: custom assistant if it recurs).
2. **The Same Question, Again** — answer routine HR questions from an approved document. Best: **reusable custom assistant** (acceptable: conversational assistant). Key: answers come from the approved document; hand over to HR when it is silent.
3. **The Ticket Sorter** — route emails by fixed rules. Best: **automation workflow** (none acceptable). Key: one label from a fixed list, unclear emails to a person, a log.
4. **The Hard Conversation** — prepare difficult feedback. Best: **conversational assistant** (acceptable: one-off prompt). Key: questions one at a time, role-play, anonymise, end with a plan.

## What the review checks
Five components (role, objective, constraints, permitted inputs, expected outputs — five words each) · eight quality signals (role, audience, limits, format, tone, inputs, data safety, review / uncertainty rule) · four task-specific items. The TASKS, RUBRIC & ANSWER KEY module lists the words that count.

## Debrief questions (suggested)
1. Which approach did you pick, and what made it the best fit? Which one tempted you and why was it wrong?
2. What did the review find that you had missed? What did you add after seeing it?
3. What will you check in the real output once you paste your build into an approved tool?
4. Where in your own work could a task like these be handled with AI — and which approach would you use? What must you never paste into a public tool?

## Notes
- Use the score as feedback, not for grading people. A participant can satisfy the keyword rubric with the right words and still write a weak build — read a few builds aloud.
- If the live connection drops: **Refresh** on the dashboard rebuilds from the relay history; otherwise collect the downloaded project files and use **Import**. Export CSV at the end if you want the builds.
